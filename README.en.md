# Group-Chat · Cross-session group chat for DeepSeek Harness

[中文](README.md) · [GitHub](https://github.com/Leica-Shen/deepseek-harness-group-chat) · MIT · **152 tests** · DeepSeek Harness Host + Web Client plugin

Group-Chat (package `@leica-shen/dsh-group-chat`, plugin id `group-talk-l`) lets a person talk to **existing agent sessions** as a group without merging their contexts. Each participant keeps its own conversation, model and workspace; the group is a membership + shared transcript + routing layer, not a new Session.

Route with `@alias`, `#role` or `*`. The person is `@human` and is in the room, not impersonated by a session. The product goal is not "one more chat UI": it is cross-session coordination that stays bounded when messages fan out, models loop, credentials leak or a room becomes noisy.

## 2.4.2 (patch)

Credentials are scanned in notes and `refs`; authorization payloads are rejected for every relay intent, not only `confirm`.

## 2.4.1 (patch)

### Release-blocking defects (the old 2.3.2 list)

- **No 30-second blocking send**: the panel inserts its own message optimistically; receipts fill in afterwards. Delivery has a concurrency gate (2 by default) with a 32-entry queue.
- **`pendingTimeoutMs` is real**: a 15-second maintenance pass expires stale pending rows; a restart only reconciles rows older than the timeout.
- **Counts match the list**: the human member is rendered as its own row, so the header count, list row and member section agree.
- **Truncation is explained**: "Last 20 of 62" plus "Load earlier"; messages are no longer silently missing.
- **One message-limit story**: send 2,000 (configurable), stored legacy rows up to 8,000, notes/decisions 1,000, all labelled in the UI.
- **Errors persist** until dismissed; success notices disappear after 4.5 s.
- **The target menu cannot be clipped**: fixed positioning, flips upward, arrow keys/Home/End/Esc; an over-cap `*` is a confirmable item rather than a dead grey button.
- **Audit cannot pop late**: no group, no modal.
- **Input semantics fixed**: the textarea is labelled "Message text", the menu is a real keyboard menu.
- **Hidden tabs refresh** on `visibilitychange`.
- **Deleting needs an explicit confirmation** from the model tool (`confirm: true`) and a second click in the panel.
- **Optional advisory lock**: `lockFile: true` makes a second live process read-only.

### Security, cost and privacy (S1–S19)

- **Real usage feedback** when the adapter reports usage/tokens, shown beside the estimate.
- **Broadcast preview**: `*` or an over-cap target shows recipients and estimated tokens first; a confirmed human broadcast may exceed the per-send fan-out ceiling, bounded by `maxBroadcastRecipients` and a daily broadcast budget.
- **Tiered budgets**: separate human (120) and agent (30) daily message ceilings; broadcasts have their own ceiling.
- **Compact policy**: `auto` uses full prose for 1–3 rooms, one line per room beyond that, capped at 3,500 characters.
- **Taint labels**: `human-typed | human-pasted | peer | tool`; pasted text is explicitly untrusted in the envelope and cannot become an authorization.
- **Credential scan**: private keys, AWS/GitHub/Slack/Google/Stripe/provider keys, JWTs and high-entropy blobs are refused; the person can confirm once in the panel, a model tool never can.
- **Read-only delegation**: children lose mutating/network tools by default and never get group tools.
- **Concurrency gate + emergency stop**: `maxConcurrentDeliveries`; pause one room or every room from the panel or `/group pause [room|*]`; a paused room records without waking anyone.
- **Structured refusals**: `{code, message, messageEn, retryAfterMs, suggestion}`; policy tells members to follow the suggestion instead of retrying.
- **Observability**: sends, deliveries, failures, rejection codes, estimated/actual tokens and p50/p95 delivery latency in Settings.
- **Group sensitivity**: `public | internal | secret`; a secret room is panel-only and cannot be created, sent to or delegated by a model.
- **Retention and redaction**: `retentionDays: 30` trims chat rows (audit facts stay); a single row can be redacted with a sha256 marker; exports remove credentials, emails and absolute paths.
- **Member history scope**: `memberHistoryScope: own` restricts members to rows they sent or were addressed by; `all` stays the default.
- **No leakage of other sessions**: policy and `group_talk_list` use aliases and roles, not other sessions' titles.

### Relay (S23)

- `group_talk_relay` / `group_talk_relay_reply` and `/group relay @alias <message>`: one bounded question, 10-minute TTL, real timeout timer, the answer returns to the origin conversation and **never enters a room transcript**.
- Five hard-coded red lines: no chaining, only `confirm | ask | handoff`, no imperative/authorization payloads, no automatic external action, fully visible and pausable via `/group relay pause`.

### Language and roles (S29)

- Three-state language switch (host / 中文 / English) in the panel; API calls carry `lang`, so host errors and suggestions are bilingual too.
- Members store a stable `roleId`; `#role` matches the id, the current label or either preset translation, so switching language no longer breaks routing. Legacy rows are migrated on load.
- `HH:mm` plus sticky day separators (Today / Yesterday / MM-DD); audit uses full timestamps.
- `/group` output follows `commandLang` (Chinese by default; set `en` for English); the incoming group badge follows the interface language.

### Visual work (S30)

- Messages are the main surface again: members are collapsed by default, one toolbar, an overflow menu for rename/topic/sensitivity/pause/export/settings/delete, and dangerous actions no longer sit under the send button.
- 12 px metadata, 13/21 px body, initial avatars, same-sender grouping within five minutes, copy on every message, safe link handling, long-message collapse that preserves scroll position.
- Amber unread instead of theme blue; the version banner uses an informational tone; `prefers-reduced-motion` is respected.
- Group id is collapsible and copyable; the group list is searchable, mutable, hideable and has "mark all read".

### Architecture (S24–S28)

- `lib/adapters.js` defines the Host boundary (`capabilities / listSessions / prompt / startSubagent`). The DSH adapter is unchanged in behaviour; a mailbox adapter serves hosts that cannot inject a turn (Codex CLI, Aider) and says so instead of pretending to wake them.
- `bin/mcp-server.mjs` exposes the same store over MCP (list/send/history/note/relay) for non-DSH hosts; `COMPATIBILITY.md` is the eight-host matrix and `ADAPTERS.md` is the integration guide.
- `DESIGN.md` documents the data flow, adapter contract, relay state machine and threat model.

### Explicit non-goals

- No attachments, images or voice; messages are text plus `refs`.
- No end-to-end encryption; at-rest protections are 0600, an optional lock and redacted export.
- Not a multi-tenant boundary; every plugin under the same OS user shares one trust domain.
- "Read" is derived (the recipient later spoke in the room), not a strongly consistent receipt; use relay when an explicit confirmation matters.
- Two processes writing one `dataFile` are not coordinated beyond the advisory read-only lock.

## Install

No runtime dependencies outside the Harness profile. Host code uses Node built-ins; the client uses the Harness React and UI primitives.

```bash
# Option A: straight from GitHub
dsh plugin --profile desktop add github:Leica-Shen/deepseek-harness-group-chat

# Option B: clone and link
git clone https://github.com/Leica-Shen/deepseek-harness-group-chat.git
cd deepseek-harness-group-chat
dsh plugin --profile desktop add link:"$PWD"
```

Confirm the profile lists `@leica-shen/dsh-group-chat` in `dsh.profile.bundles`, then **restart Harness once**. The Host half is cached in the process; a page refresh alone does not replace it.

## Usage

- Sidebar **Group chat**, the header button in a conversation, or the panel's "New group chat".
- `/group @alias <message>`, `/group #role <message>`, `/group * <message>`.
- `/group relay @alias <message>` for a one-to-one confirmation.
- `/group pause [room|*]`, `/group resume [room|*]`, `/group topic <text>`, `/group export`, `/group cleanup`, `/group stats`.
- Model tools: `group_talk_list`, `group_talk_send`, `group_talk_history`, `group_talk_leave`, `group_talk_note` (note/decision), `group_talk_relay`, `group_talk_relay_reply`; `group_talk_delegate`, `group_talk_manage`, `group_talk_create` only when enabled.

## Security posture

A group message is untrusted peer content (or explicitly labelled human-pasted content); a human-typed message is a user instruction. Sending is durable once accepted; rejected sends are not delivered. Budgets are estimates, not bills. The store is a plain JSON file (0600) under `$DSH_HOME`; do not paste credentials, and prefer a path or an environment-variable name. See [SECURITY.md](SECURITY.md) for the full model.
